## 2026-03-23 Telegram restart persistence

- Goal: make the personal Telegram runtime keep logical Codex conversations across bot restarts on the same host.
- Implementation:
  - updated `src/telegram-entry.js` to resolve runtime storage paths from env and create file-backed task/session/source-binding repositories by default;
  - wired Telegram startup to `recoverRuntimeState(...)` so interrupted runs are marked and ready sessions remain available;
  - returned repository and recovery handles from the runtime for verification and future service wrapping.
- Tests:
  - extended `tests/telegram-entry.test.js` with restart persistence coverage;
  - verified `npm test` passes with `58/58`.
- Delivered behavior:
  - after `/create` and at least one successful `/send`, restarting `npm run tg:bot` on the same machine keeps the saved `codexThreadId` and source binding;
  - the next plain-text Telegram message from the same allowed chat resumes the prior Codex conversation.
- Known limit:
  - this does not resume a task that was still executing at shutdown; those are recovered as interrupted.
