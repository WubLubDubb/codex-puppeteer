## 2026-03-22 Telegram UTF-8 Transport Fix

- Root cause: Windows PowerShell transport could return Telegram JSON through a non-UTF-8 console code page, which corrupted Chinese text from getUpdates before Node parsed it.
- Change: `src/telegram-client.js` now wraps PowerShell JSON output as base64-encoded UTF-8 and decodes it in Node before JSON.parse.
- Change: PowerShell send requests now use `application/json; charset=utf-8` with UTF-8 request bytes.
- Verification: added Telegram PowerShell UTF-8 regression coverage in `tests/telegram-client.test.js` and `npm test` passed with 53/53.

## 2026-03-22 Wait Output Filtering Fix

- Root cause: `/wait` still treated Codex terminal chrome as meaningful output in some real sessions.
- Change: `src/output-analysis.js` now classifies `directory:`, `OpenAI Codex (...)`, `Tip: ...`, and prompt echoes prefixed by `>`, `>_`, or `U+203A` as non-meaningful UI/prompt lines.
- Verification: added regression coverage in `tests/output-analysis.test.js`; `npm test` passed with 54/54.
## 2026-03-22 Exec Driver Switch

- Switched the primary real Codex control path from interactive PTY injection to `codex exec --json` plus `codex exec resume`.
- Added `ExecCodexAdapter` in `src/codex-adapter.js` and made real mode default to `CODEX_PUPPETEER_TERMINAL_DRIVER=exec`.
- `thread.started` JSON events now persist `codexThreadId`, so a logical session created by `/create` can resume context across later `/send` calls.
- Session lifecycle is now split into reusable `ready` and in-flight `running` states. `/create` creates a reusable session; `/send` starts one exec run; run completion returns the session to `ready`.
- Updated `src/automation-agent.js` and `src/session-repository.js` for driver metadata, thread id persistence, reusable session state handling, and binding preservation after an exec run completes.
- Expanded regression coverage in `tests/codex-adapter.test.js`, `tests/automation-agent.test.js`, `tests/wait-detection.test.js`, and `tests/repository-persistence.test.js`.
- Verification: `npm test` passed with `56/56`.
- Current recommended manual validation: restart `npm run tg:bot`, create one session, send one prompt, then confirm `/wait` returns real assistant content from the exec backend instead of TUI echo.

## 2026-03-22 Windows Codex Spawn Fix

- Root cause of `spawn codex ENOENT`: on this Windows host, `codex` resolves to Node-installed shims (`codex`, `codex.cmd`, `codex.ps1`), and direct Node `spawn("codex")` is not reliable for the PowerShell/cmd shim path.
- Fix: `src/codex-adapter.js` now wraps non-exe Windows Codex launches through `cmd.exe /d /s /c ...`, and uses PowerShell explicitly if a `.ps1` path is configured.
- This keeps the new `exec/resume` backend unchanged while making Windows launch semantics match how the command works in a normal terminal.
- Verification: `npm test` remains green at `56/56`.
