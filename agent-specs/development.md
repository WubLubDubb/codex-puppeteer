# 代码开发规范

## 1. 用途

用于指导代码实现、测试补充、实现偏差记录和开发日志更新，使实现与需求、设计、计划保持一致。

## 2. 何时参考本规范

- 用户要求实现、修改、重构、修复或补测某项功能。
- 需要根据新的需求、设计或计划调整现有实现。
- 需要根据测试结果或线上问题修复实现，并回写开发记录。

## 3. 可参考输入

- `docs/requirements.md`
- `docs/system-design.md`
- `docs/development-plan.md`
- `docs/change-log.md`
- `.agent/current-state.md`（如已存在）
- 最近相关的 `docs/dev-logs/` 日志
- 现有代码与测试结构

## 4. 输出

- `src/` 下的实现代码
- `tests/` 下的测试代码
- `docs/change-log.md` 中的当前开发状态与日志索引
- `docs/dev-logs/<YYYY>/<YYYY-MM-DD>.md` 中的当日开发记录
- `.agent/current-state.md` 中的当前开发上下文摘要
- 如有必要，回写设计或计划文档

## 5. 开发规则

- 若缺乏对话上下文，应先读取 `docs/change-log.md`、`.agent/current-state.md` 和最近相关的 `docs/dev-logs/` 日志，再开始开发。
- 实现优先级应与开发计划一致。
- 每项主要实现应可映射到需求编号。
- 开发过程中若发现设计不完整，应先回写设计，再继续实现。
- 所有关键逻辑都应有对应测试或验证说明。
- 每完成一个有意义的开发动作后，都必须向当日日志追加一条记录，而不是只在阶段结束时记录。
- 每条开发日志至少应包含：本次目标、完成内容、关键实现点、对应需求或设计、影响文件、验证结果、未完成事项、风险或阻塞、下一步建议、给下一个 agent 的接手提示。
- 若本次开发改变了当前系统状态、未完成事项、阻塞或下一步建议，必须同步更新 `docs/change-log.md` 与 `.agent/current-state.md`。
- 不允许只写代码不更新文档状态。

## 6. 开发日志最低结构

- `docs/change-log.md` 至少应能看到：当前状态、最近完成内容、关键文件入口和日志索引。
- `docs/dev-logs/<YYYY>/<YYYY-MM-DD>.md` 中的每条开发记录至少应包含本次目标、完成内容、影响文件、验证结果、未完成事项和接手提示。

## 7. 停止条件

- `docs/requirements.md` 或 `docs/system-design.md` 缺失，无法安全实现。
- 上游文档与现有实现明显冲突，且无法判断应以哪一方为准。
- 用户需求存在互斥约束，继续编码会扩大偏差。

## 8. 完成定义

代码开发完成至少满足以下条件：

1. 目标功能已实现。
2. 关键路径已有测试或验证证据。
3. `docs/change-log.md` 已更新当前开发状态与最近完成内容。
4. 当日日志已写入 `docs/dev-logs/<YYYY>/<YYYY-MM-DD>.md`。
5. `.agent/current-state.md` 已更新实现映射、阻塞和下一步建议。
6. `.agent/traceability.md` 已更新实现映射。
7. 若实现偏离原设计，偏差已记录。
